# YUI — Автономный локальный AI-агент

Это попытка сделать проект основанный на вайбкоде. Основной код пишется нейросетью, и лишь дорабатывается человеком.

**YUI** — это локальная автономная цифровая сущность, предназначенная для прямого взаимодействия с операционной системой Windows. Проект построен вокруг легковесной LLM (оптимизировано под модели ~4B параметров, такие как Gemma 4) и запускается полностью оффлайн через `llama.cpp`.

В отличие от обычных чат-ботов, YUI обладает долговременной файловой памятью, динамической "душой" (эволюционирующей персоной) и способностью к спонтанной активности, когда пользователь отходит от компьютера.

## 🧠 Ключевые особенности

- **Управление ОС (Computer Use):** Открытие приложений, эмуляция ввода текста (через буфер обмена для стабильности), нажатие хоткеев, убийство процессов.
- **Семантическая память без векторных БД:** Самописный `MemoryManager`, использующий индекс Жаккара для поиска, дедупликации фактов и разрешения конфликтов "серой зоны" (когда старый и новый факт похожи, но не идентичны).
- **Динамическая "Душа" (Soul System):** `SoulManager` анализирует папку с памятью перед каждым запросом и инжектит в системный промпт "заплатку" с информацией о пользователе и саморефлексией YUI. Агент меняет тон в зависимости от того, с кем говорит.
- **Режим автономности:** Фоновый поток (`AutonomyManager`) через WinAPI отслеживает бездействие пользователя. Если пользователь молчит более заданного времени, YUI генерирует спонтанную мысль или реплику.
- **Агрессивная санитария контекста:** Специально разработано для маленьких моделей (4B). Включает схлопывание рекурсивных XML-тегов, экстренную резку контекста при переполнении VRAM и глубокий парсинг JSON из "мусорных" ответов нейросети.
- **Модуль зрения:** Готовый инструмент для захвата экрана с агрессивным даунскейлом до 1024x1024 (JPEG) для экономии токенов.

## 🏗 Архитектура проекта

```
.
├── agent_loop.py           # Главный цикл агента (оркестратор, парсинг, fallback-механизмы)
├── core/
│   ├── prompt_builder.py   # Генерация системного промпта (инжект железа, времени, souls)
│   ├── session_manager.py  # Сериализация/десериализация сессий в JSON
│   ├── soul_manager.py     # Динамическая генерация "персоны" на базе /memory
│   └── autonomy_manager.py # Фоновый поток спонтанной активности (WinAPI idle checker)
├── pc_interaction/
│   └── control.py          # Прослойка для управления Windows (keyboard, pygetwindow)
│   └── (unused)vision.py       # Захват экрана в base64
└── memory/
    └── memory_manager.py   # Файловая БД (чтение, поиск, Jaccard-дедупликация, конфликты)
```

## ⚙️ Как это работает (Жизненный цикл)

1. **Запрос:** Пользователь вводит задачу. `agent_loop` формирует сырой Gemma-промпт.
2. **Размышление:** Модель генерирует ответ внутри тегов `<thought>`.
3. **Действие:** Если нужен инструмент, модель выдает `<instrument_call>{"tool": "...", "params": {...}}</instrument_call>`.
4. **Исполнение:** `ComputerControl` или `MemoryManager` выполняют команду на ОС.
5. **Цикл:** Результат возвращается модели в виде `<system_event>`. Цикл повторяется до вызова `task_complete`.
6. **Извлечение фактов:** При завершении (или обрыве) отдельный легковесный вызов LLM выковыривает из истории важные факты и раскладывает их по папкам вида `[category/topic].md`.

## 🛠 Требования

- **ОС:** Только Windows (используется WinAPI, `pygetwindow`, вызовы `nvidia-smi`).
- **Python:** 3.10+ (используется синтаксис `X | Y` для типизации).
- **Бэкенд:** Запущенный сервер `llama.cpp` на `http://127.0.0.1:8080/completion` (рекомендуется модель с поддержкой нативных тегов размышлений, например Gemma 4).
- **GPU:** Рекомендуется NVIDIA (для мониторинга температуры и VRAM через промпт).

## 🚀 Установка и запуск

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/your_username/yui-agent.git
   cd yui-agent
   ```

2. Установите зависимости:
   ```bash
   pip install requests mss pillow pyperclip keyboard pygetwindow
   ```

3. Запустите ваш `llama.cpp` сервер (пример):
   ```bash
   ./llama-server -m gemma-4-4b-it-Q4_K_M.gguf -c 65536 --port 8080
   ```

4. Запустите агента:
   ```bash
   python agent_loop.py
   ```

## ⚙️ Настройка (Конфигурация)

В `agent_loop.py` есть базовые настройки:
- `ENABLE_AUTONOMY = False` — поменяйте на `True`, чтобы включить фоновую генерацию мыслей при бездействии ПК.
- В `autonomy_manager.py`: `idle_threshold=300` (время бездействия в секундах для триггера) и `check_interval=600` (частота проверок).

## 📂 Система памяти (Особенности)

Память хранится в папке `/memory` в виде обычных `.md` файлов. 
- **Структура:** Максимум 2 уровня вложенности (например `biology/axolotls.md`).
- **Дедупликация:** Используется коэффициент Жаккара. Если новый факт совпадает со старым >70% — старый перезаписывается. Если совпадение 40-70% — возникает "Серая зона". Агент получает уведомление о конфликте и сам решает, перезаписать факт или сохранить оба.
- **Скрытые триггеры поиска:** 
  - `search_memory(query="__tree__")` — показывает структуру папок.
  - `search_memory(query="__all__")` — выгружает всю память.
  - `search_memory(query="FILE:user/dislikes")` — читает конкретный файл.

## ⚠️ Ограничения и защитные механизмы

Так как проект заточен под 4B модели (которые склонны к галлюцинациям и слому формата), реализовано множество защит:
- Жесткая обрезка физических переносов строк внутри JSON-вызовов инструментов.
- Схлопывание рекурсии тегов (если модель начнет писать `<output><output><output>`).
- Экстренный дамп истории в память при получении HTTP 400 от `llama.cpp` (переполнение контекста).
- Время ожидания (`wait`) жестко ограничено 300 секундами, чтобы агент не "завис" навсегда.
